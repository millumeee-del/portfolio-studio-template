# 从原型到可维护网站：搭建逻辑与流程

## 1. 先把视觉目标拆成可复用模块

先确定首页、作品总览、分区、作品详情、About、SHOWREEL 这六种页面，再抽出共同导航、侧栏、联系方式和语言切换。页面负责组合，组件负责一项明确功能，CSS 负责视觉规则，浏览器脚本负责交互。

这避免了每页各写一份菜单、改一次字号要到处找代码的情况。共同内页壳是 `src/layouts/PortfolioLayout.astro`，页面网址由 `src/pages/` 的目录结构生成。

## 2. 使用 Astro 生成静态页面

作品内容在构建时读入，生成 HTML、CSS 和 JavaScript。观众访问时直接拿到主要内容，不必先请求一个内容数据库再等前端拼整页。Three.js、拖拽编辑等交互在需要时交给浏览器脚本。

执行链：`src/data + src/pages + components → astro build → dist → 静态托管`。这是作品集的内容发布链；线上贴纸是另外一条需要数据库的链。

## 3. 内容与样式分离

`src/data/works.json` 存标题、年份、分区、封面和正文块；`categories.json` 是首页滚轮、侧栏和路由的共同分类来源。`portfolio.ts` 把数据转换成页面能使用的列表与链接。图片、视频、模型放 `public/`。

通用字号、边距、颜色、手机覆盖值集中在 `site-settings.css`。单个作品的自由布局单独存数据，因此修改通用样式不会抹掉每个作品的排版。

## 4. 做一个只在本地工作的轻量内容编辑器

Astro 开发环境中的 Vite 插件提供本地接口：作品增删、上传素材、保存排版和手工译文。浏览器把修改提交给这些接口，接口校验后写入 JSON；保存前备份、版本哈希与写入队列用于降低误覆盖和并发冲突。

编辑入口由 `import.meta.env.DEV` 控制；正式构建不输出编辑页面和保存接口。它是本地创作工具，不是线上多人 CMS。共享源代码的人在自己电脑编辑，再重新构建发布。

## 5. 从固定排版发展成自由画布

作品正文用文本、图片、视频、间隔等内容块表达；自由画布额外记录每个框的 x、y、宽、高、字号。Pointer Events 统一鼠标与触控输入；pointer capture 保证手指或鼠标离开框后仍可继续拖动。

拖动时以参考画布宽度换算坐标，拖到相邻边缘、中心线附近时吸附。缩放根据手柄方向更新尺寸。画廊按原图比例和行宽计算布局；最后一行允许留白，避免最后一张被强制拉满。

About 使用同类思想，但文本框各自独立。头像形状是四个角点组成的 CSS polygon；拖动角点修改裁切形状，不改原图像素。替换头像只改图片路径，保留框的尺寸和裁切。

## 6. 双语不是把全站字符串直接替换

标题可填写中英文两版；正文译文使用作用域隔离，作用域是具体帖子的 URL。这样两个项目即使有相同中文句子，也能有不同英文。手工译文存 `translations.en.json`，没有云端自动翻译费用，也不会覆盖手动调整。

切换语言后测量真实文本高度，重新推进后续内容，避免英文多换一行造成重叠；不能只比较字符数量，也不能反复累加旧的高度增量。

## 7. 3D 首页的加载与动画同步

Three.js 的 GLTFLoader 读取 GLB，统一计算包围盒、相机距离、模型中心与地面位置。渲染循环推进动作、鼠标旋转与反馈，离开视口时减少无效渲染；离开页面时释放监听器、材质和纹理。

多模型切换保留当前动作相位和视角，而不是每次重播第 0 帧。此前动画跳动排查的关键是检查实际片段时长、循环边界、相位对齐和根节点变换，不能只依据导出时的帧数标签。通用示例模型使用自身的闭合动作。原实现还保留了可选的同名骨骼共用动作、眨眼、头部跟随和附件反馈代码；这些功能需要匹配的模型骨骼和贴图，不是任意 GLB 的自动功能。

## 8. 分类滚轮与 SHOWREEL 循环

分类滚轮用一个连续位置值决定每项到中心的距离，距离映射为位置、大小和透明度；滚轮、触控、键盘更新同一份状态。

SHOWREEL 默认进入 ALL，然后按三个年份排列。URL 查询参数保存当前年份，所以可以直接分享某段视频。跨过最后一段时临时调整同一组真实面板的位置，只滑动相邻一屏，再在同一帧还原顺序。这样可以循环，又不会复制带播放器状态的视频节点。

圆环目录在 `ShowreelDirectory.astro` 保留：卡片位置由圆心、半径、角度计算，卡片横轴沿所在点的外法线，中心卡水平。它目前没有挂到公开路由，恢复时需要导入该组件。

## 9. 心情贴纸的数据链

浏览器先创建草稿，允许选图案、输入文字、拖动和等比缩放；确认后才写入后端。每张贴纸保存页面、相对位置、尺寸、旋转和留言。客户端持有随机撤回凭据，服务器只存其哈希；更新与删除必须验证归属，不把凭据发给其他观众。

本地使用 SQLite；线上可使用 Workers 的 API + D1。共享后端需要来源检查、参数校验、长度限制、频率限制、页面校验和删除能力。模板保留这些逻辑，但不包含任何历史留言或账号。

## 10. 手机不是简单缩小电脑截图

电脑上的自由坐标到了窄屏会变成阅读流：内容框按顺序排列，图像等比限高，正文使用手机字号；About 把头像和简介排到上下。主页与导航有独立手机参数，手机和电脑的排版保存互不覆盖。横屏需要额外检查可用高度，避免联系方式把视频挤没。

## 11. 验证与发布

先验证数据校验、循环数学、译文隔离和贴纸归属，再在浏览器实测拖动、保存、刷新恢复、双语及窄屏。最后构建正式版，检查路由、素材引用与编辑器是否被剔除。

个人生产工程原先还有按实际素材生成缩略图、GIF 转视频、H.264 / faststart、首帧预览、屏内加载、模型压缩与缓存版本等发布优化。这些需要额外的 FFmpeg、压缩依赖和主机配置；本模板提供轻量样例与标准静态构建，不携带那套绑定具体电脑的发布脚本。替换为大素材后，应根据部署限制另做压缩与加载优化。

## 12. 最适合复用的工作方法

先有能运行的纵向完整页面，再逐步把写死的内容变成数据，把固定数值提炼成参数，把重复页面提炼成组件。每次先明确期望行为与复现场景，修完验证触发场景，再检查手机和正式构建。备份、版本校验、源码与产物分离，比继续叠加临时补丁更有价值。
